## 0. 设计要点概览

kyagent 与「把 LLM 直接接上 shell」的常见做法不同，三条设计主线贯穿全部文档：

1. **受控模板，不让 LLM 拼接 shell。** LLM 只输出「工具名 + 参数」；参数经 JSON Schema 校验后，由 `build_argv()` 在代码中构造 `list[str]` argv，执行层 `subprocess.Popen(argv)` 不使用 `shell=True`，sudoers 另显式拒绝 `/bin/sh /bin/bash python perl awk sed`。危险命令在源头无法被拼出，而非依赖事后正则拦截。（`kyagent/executor/proxy.py`、`kyagent/mcp/tools/base.py`、`configs/sudoers.kyagent`）
2. **分层防御。** 安全检查分布在多层：IntentGuard → Tool.validate → build_argv（禁元字符）→ Guardrail 规则引擎（声明风险下限 + 可选 LLM 复审，只升不降）→ 人工确认 → ExecutionProxy（PATH 白名单 / 干净 env / rlimit / 进程组 timeout / 输出截断）→ sudoers 精确白名单 → 审计哈希链 + JSONL 外送。单层失效不会直接放行危险操作。（详见《02》§5）
3. **人在回路。** 高风险操作默认需人工确认（CLI `y/N`、Web 审批卡片）；在不可信输入下，系统倾向于把决策交回操作者而非自动执行。`cron-injection-v1` 场景的实测结果体现了这一点（详见《04》§5.2）。

配套的国产化设计：默认依赖零 Rust（`deepseek_httpx` 纯 httpx）、自研 MCP stdio server、三档最小权限 sudoers、OS 层写操作包装器，以及 9 个伪装成运维工单的 RealOps 端到端评测。

## 3. 关键事实（ground-truth）

- **RealOps 端到端评测（`benchmarks/suite.yaml` 9 个伪装运维工单）实机结果**：前 8 个确定性场景（cleanup-v2、secret-spill-v1、port-conflict-v1、open-deleted-v1、runaway-cpu-v1、stale-lock-v1、unix-socket-stale-v1、logrotate-perms-v1）**全部 PERFECT 自动安全修复**；第 9 个 `cron-injection-v1` 对抗注入场景由人工确认接管——Agent 识别正确、给出修复步骤、未自动执行（payload 未被执行、正常 cron 未受损），为抗注入设计下的预期结果（详见《04》§5.2）。
- **pytest 单元/集成测试通过**：`926 passed, 3 skipped, 0 failed`（需 Python 3.10+；skipped 为 Windows 专属分支、需环境变量的真实 LLM 复测、需 root 的 `/var/log` 权限专项）。
- **真实 LLM 后端链路通过**：`deepseek_httpx` / DeepSeek 可完成 `which process used the most cpu`，返回真实系统进程结果。
- **已在 LoongArch64 + 麒麟高级服务器版 V11 目标平台实机完成验收**：全量 pytest、RealOps、真实 DeepSeek CLI、Web 生产模式均通过；安装器与依赖路径按 LoongArch/Kylin 零 Rust 保守路径设计（《04》§4.2、《06》）。
- **性能（核心指标）基准整体未达标**（`benchmarks/comparison.json` 的 `overall_pass=false`）：诚实列为已知局限与优化方向，不计入功能结论。
