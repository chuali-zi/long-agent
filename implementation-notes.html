设计决策2026-05-22 选方案 B（HttpxBackend）

选择：新增 HttpxBackend 类，与 OpenAIBackend 平级实现 LlmBackend 抽象接口；内部不 import openai，直接用 httpx.Client POST /chat/completions。_construct_backend 工厂新增三个等效分支：openai_httpx / deepseek_httpx / qwen_httpx，复用 cfg.agent 现有 openai/deepseek/qwen 子节，无需新增 Pydantic 字段。配置切换由 KYAGENT_DEEPSEEK_TRANSPORT 环境变量驱动（deepseek.yaml 内 llm_backend: ${KYAGENT_DEEPSEEK_TRANSPORT:-deepseek}）。

依据：

  • 抽象层契约保障：Agent.core / cli / runtime / tests 全部通过 LlmBackend.chat() 接口调用，不感知具体后端。HttpxBackend 输出与 OpenAIBackend 等价的 AssistantMessage → 调用方零改动

  • OpenAIBackend 类完整保留 → Windows/macOS/x86 Linux 等正常环境继续走 SDK 路径，回归零风险

  • 零新增依赖：httpx 已在 requirements-loongarch.txt 第 24 行（作为 anthropic 0.39.0 的运行时依赖手动补齐项），HttpxBackend 直接复用，不动 requirements-loongarch.txt

  • 边界场景：choices=[] 时返回空 AssistantMessage 不崩；未知 finish_reason 原样透传（OpenAI 协议未来扩展兼容性）
