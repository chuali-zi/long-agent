# 龙芯（LoongArch64 Old World，Kylin V10）专用依赖清单
# 配合 DEPLOYMENT-LOONGARCH.md 第 6.4 节使用。
# 设计依据：implementation-notes.html
#   - "2026-05-22 龙芯依赖替换方案 A"
#   - "2026-05-23 PyYAML sdist 行为纠偏"
#   - "2026-05-23 通用入口防护：anthropic 移成 optional"
#
# 默认安装方式（不带 anthropic backend，零 Rust 风险）：
#   pip install --upgrade "pip>=23" setuptools wheel
#   pip install --no-binary PyYAML -r requirements-loongarch.txt
#   pip install -e .                  # 主依赖只装一次，无 --no-deps 需要
#
# 可选：要用 Anthropic Claude backend 时（默认推 DeepSeek，走 deepseek_httpx 不需要这步）：
#   pip install --no-deps "anthropic==0.39.0"   # --no-deps 绕开 jiter Rust
#   # 然后手补下方 "Anthropic backend optional deps" 段（distro 等）
#
# 编译保证：
#   - 无 Rust 编译：主依赖（pydantic v1 + httpx + 其他纯 Python）全部 py3-none-any 或纯 sdist；
#     anthropic 走 --no-deps 时不拉 jiter，可选段只补纯 Python deps
#   - PyYAML 的 _yaml libyaml C 扩展"会被尝试编译"：sdist 安装时 setup.py 默认启该路径，
#     缺 libyaml-devel 时 CompileError 被 setup.py 捕获 → 自动 fallback 到纯 Python SafeLoader，
#     install 仍成功（pip 日志含 'fatal error: yaml.h' 警示行，非终止错误）。
#     装了 libyaml-devel → C 扩展编译成功，yaml.__with_libyaml__=True，加载略快。
#   - 严格说不是绝对零 C 编译尝试，但 PyYAML 的 fallback 机制保证 install 一定成功。

# === 主依赖（pyproject.toml [project.dependencies] 同步）===
# 全部 LoongArch 安全：无 Rust 编译需求，pip install -e . 可放心默认走这条
pydantic>=1.10.13,<2
# PyYAML 最低 6.0.1：6.0.0 的 pyproject.toml 没给 Cython 上限，Cython 3.x 下 sdist
# 构建会失败 (PyYAML issue #736: AttributeError: cython_sources)
PyYAML>=6.0.1,<7
typer>=0.12
rich>=13.7
# httpx 是 HttpxBackend 用的（DeepSeek/Qwen/OpenAI 兼容协议走 deepseek_httpx），
# 纯 Python，2026-05-23 起从 anthropic 的 transitive 提升到主依赖
httpx>=0.23.0,<1

# === Anthropic backend optional deps（仅当装了 --no-deps anthropic==0.39.0 时补齐）===
# 这些是 `anthropic==0.39.0` 的 Requires-Dist 减去 jiter 后的纯 Python 子集，全 py3-none-any。
# 注：httpx 已在主依赖段，不在这里重复；anyio / sniffio / typing-extensions 是 httpx
# 的 transitive 依赖（pip 装 httpx 时已带），重复列出是为了显式声明 anthropic 也需要它们。
anyio>=3.5.0,<5
distro>=1.7.0,<2
sniffio
typing-extensions>=4.7,<5
