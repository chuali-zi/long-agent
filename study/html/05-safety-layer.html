1 四级流水线总览

2 RiskLevel 与 Decision

RiskLevel
low order = 0
大多数感知工具（process_list / fs_df / lsof_port）
RiskLevel
medium order = 1
svc_reload / ufw disable / sysctl-rewrite
RiskLevel
high order = 2
svc_restart / chmod 777 / iptables -F
RiskLevel
critical order = 3
rm -rf / · dd of=/dev/sda · :(){:|:&};:

order 属性让 risk 可以排序——这是「取最高 risk」的基础。在 LLM 复审分支里，「升级」指的是 new_decision.order > old_decision.order，确保复审不能放水。

3 Rule 数据结构

3.1 字段语义

id
规则唯一 id，命中后留在 Hit.rule_id
risk
命中时贡献的 risk 等级
pattern
在完整 cmdline 上做的正则匹配（re.search）
command
argv[0] 的 basename（如 rm、chmod）
flags_any
argv[1:] 中 flag-style token 至少出现一个
flags_all
argv[1:] 中 flag-style token 必须全部出现
target_in
argv[1:] 中至少一个非 flag token 落在这些前缀路径下
AND
单条规则内部：所有非空字段是 AND 关系（都满足才命中）。
多条规则之间：是 OR 关系（任一命中都计 hit）。

5 一条规则示例 + 匹配三件套

configs/safety-rules.yaml
- id: rm-recursive-system
  risk: critical
  description: 递归删除关键系统目录
  command: rm
  flags_any: ["-rf", "-fr", "-r", "-R", "--recursive"]
  target_in:
    - "/etc"
    - "/usr"
    - "/var"
    - ...
1
argv[0] basename = rm
2
argv 中至少一个 flag 在 flags_any 列表
3
argv 中至少一个非 flag 参数落在 target_in 任一前缀下
SAFE
避免误伤：/tmp 没在 target_in 里，所以 rm -rf /tmp/cache 是 ALLOW。 / 也没在 target_in 里（单独的根删除由 dangerous-rm-pattern 处理）。

6 RuleEngine 关键细节

6.1 进程级 LRU 缓存（rules.py:100）

★ rules.py · scan_cmdline
def scan_cmdline(self, cmdline: str) -> list[Hit]:
    cached = _scan_cached(cmdline, self._version, id(self))
    if cached is not None:
        return list(cached)

    hits = self._scan_uncached(cmdline)
    _scan_store(cmdline, self._version, id(self), tuple(hits))
    return hits

键是 (cmdline, rules_version, engine_id)：

  • cmdline — 同一条命令必产生同样 hits
  • rules_version — 规则集变了自动失效（fingerprint）
  • engine_id — 多个 RuleEngine 实例（测试场景）互不串味
PERF
性能影响（benchmarks 数据）：guardrail p50 从 21.9μs 降到 1.9μs（-91%）。

6.2 _fingerprint · 规则集指纹

把所有规则的关键字段拼起来做 sha256。分隔符用 \x1f（US, Unit Separator）和 \x1e（RS, Record Separator），确保不和规则内容碰撞。任何字段改动都会改变指纹。

6.3 _match · flag 容错拆分

rm -rf /etc 中 -rf 是一个 token，被拆成 {-r, -f}，于是 flags_all=["-r","-f"] 也能命中。这阻止了通过「合并 flag」绕过规则的攻击。

6.4 _path_under · 用 posixpath 而非 os.path

CROSS-OS
目标系统是 Linux/麒麟，但开发可能在 Windows 上。os.path 在 Windows 上会把 /etc 翻成 \etc 影响判断。必须用 posixpath。

7 Guardrail._check 主方法 · 关键设计

1
declared_risk 作为下限：永远不会降级（order > risk.order 才覆盖）
2
LLM 复审只能升级：同样的 order 比较
3
复审异常不抛：记 rationale 后继续（防止 LLM 后端波动卡死安全流水线）
!
declared_risk 是下限不是上限。工具声明 LOW 永远不能把规则命中的 CRITICAL 降下来。这条不变量被 test_safety.py::test_declared_risk_does_not_downgrade 锁死。

9.3 边界用例锁死

1
rm -rf /tmp/build-cache → ALLOW（不在 target_in 列表）
2
rm '-rf' '/etc'（带引号）→ DENY（shlex 切词后仍识别）
3
rm -rf /usr → 同时命中 rm-recursive-system + dangerous-rm-pattern（flag 拆分）
4
systemctl restart sshd + declared HIGH → CONFIRM
5
rm -rf /etc + declared LOW → DENY（declared 是下限，不降级）

10 CLI · 离线测一条命令

kyagent safety test "rm -rf /etc"

会得到一个红色 Panel，里面写着 decision: deny、risk: critical、命中规则 + 完整 rationale。完全离线，不会真正执行。

11 关键不变量

1
declared_risk 是下限：永远只能升 risk，不能降
2
LLM 复审是升级器：只在 reviewer 返回更高 risk 时才生效
3
复审异常不影响安全决策：catch 后继续，rationale 留痕
4
scan_cmdline 是纯函数（除了 LRU 缓存）：同样输入 + 同样规则集 = 同样 hits
5
规则集变更自动失效缓存：通过 fingerprint 隔离
