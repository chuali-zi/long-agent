3 关键不变量

1
executor 不知道 safety — 任何防护都是上层（Agent / McpServer）调用 guardrail.check_argv 后再交给 executor。这避免「执行器自己短路安全检查」的反模式。
2
safety 不知道 executor — 只接收 cmdline / argv，不真正运行。意味着 kyagent safety test 子命令完全离线、零副作用。
3
audit 是所有人都可以 event()，但不反向调用其它模块（无回调、无 hook）。审计是纯下游。
4
mcp.tools 完全独立于 agent.llm — 工具的 input_schema 是 JSON Schema，to_anthropic_tools() / to_mcp_list() 是简单序列化，未来加新后端不需要改工具。

6 模块边界 = 安全边界

每一条模块边界都对应一条安全断言。这是这个项目的灵魂。

边界强制约束实现位置
LLM → Agent只能返回 tool_use 块，不能塞 raw shellagent.llm.AssistantMessage.tool_uses()
Agent → Toolargs 必须过 Tool.validate() 才进 build_argvagent/core.py:247-249
Tool → Executor只接 list[str] argv，不接字符串Tool.build_argv() -> list[str]；executor 全程不调 shell
Agent/MCP → Executor必须经过 Guardrail.check_argv 才能落地agent/core.py:261 + mcp/server.py:162
Executor → 子进程没有 shell=True、PATH 白名单、env scrubexecutor/proxy.py:140-149
工具 → 路径黑名单（/etc/shadow、systemd-logind）service.py:_validate_unit、filesystem.py:_safe_path
所有阶段 → audit每一步 audit.event 写入 trace主循环 + MCP 调用都有 7 段事件

7 最小心智模型

「自然语言进来，argv 出去，结果回去」 — 七个变换、每一步都有审计事件。这个 pipeline 就是赛题「完整闭环日志」的物理实现。

STEP 2 · LLM
