2 Trace · 单次 turn 的容器

trace_id
trace-{uuid hex[:12]} · 唯一
user
interactive / oneshot / mcp-client
started_at
time.time() · unix 秒
events
list[TraceEvent] · 内存中
metadata
backend / channel / tool 等附加信息
_seq
内部计数器，下一个事件的 seq
_lock
RLock（可重入！因为 logger.event 持有锁时调 trace.add 又 with lock）
audit/trace.py:53 · add() 全锁内
def add(self, kind: EventKind, payload: dict = None) -> TraceEvent:
    with self._lock:
        self._seq += 1
        ev = TraceEvent(seq=self._seq, kind=kind, ts=time.time(),
                        payload=payload or {})
        self.events.append(ev)
        return ev
RLock
必须是 RLock 不是 Lock。否则 logger.event with trace._lock 后再调 trace.add（内部也 with lock）就会死锁。

4 H1 修复 · _jsonl_fp 的 TOCTOU 防御

audit/logger.py · 修复后的正确模式
with trace._lock:
    ev = trace.add(kind, payload)
    self.store.append_event(trace.trace_id, ev)

    if self._jsonl_fp is not None:        # 仅作 fast-path 短路
        line = json.dumps(...)
        with self._jsonl_lock:
            fp = self._jsonl_fp           # 锁内 capture 到 local
            if fp is not None:            # 锁内二次判空
                fp.write(line + "\n")     # 用 local 引用写
H1
错误模式：if self._jsonl_fp: ... self._jsonl_fp.write(...) 之间 close_file() 在另一线程把 fp 置 None → NoneType.write 报错。

正确：外层 if 只作 fast-path 短路（跳过 json.dumps），真正解引用 + 写入移进 _jsonl_lock 内，先 capture 到 local 再判空。 详见 12-concurrency · H1。

5 AuditStore · SQLite WAL

5.1 Schema

CREATE TABLE traces (
    trace_id    TEXT PRIMARY KEY,
    user        TEXT NOT NULL,
    started_at  REAL NOT NULL,
    metadata    TEXT
);

CREATE TABLE events (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    trace_id    TEXT NOT NULL,
    seq         INTEGER NOT NULL,
    kind        TEXT NOT NULL,
    ts          REAL NOT NULL,
    payload     TEXT NOT NULL,
    FOREIGN KEY (trace_id) REFERENCES traces(trace_id)
);

CREATE INDEX idx_events_trace ON events(trace_id, seq);    -- 回放某条 trace
CREATE INDEX idx_events_kind  ON events(kind, ts);         -- find_events_by_kind
CREATE INDEX idx_traces_started ON traces(started_at DESC); -- list_traces

5.2 连接配置

check_same_thread=False
允许多线程共用同一 connection
isolation_level=None
自动提交模式（每条 INSERT 立即落盘）
PRAGMA journal_mode=WAL
写不阻塞读，适合「频繁追加 + 偶尔回看」
_lock = Lock()
所有 execute 过这把锁 — SQLite connection 同一时刻只能跑一条语句

6 一次 ask 的完整 7 段事件

每条事件都同步 append 到三处：Trace.events（内存）、SQLite events 表、var/audit.jsonl。全部在同一把 trace._lock 保护下，所以 seq 顺序 = SQLite 落盘顺序 = JSONL 行顺序。

seq=1
USER_INPUT
{"text": "查 80 端口"}
seq=2
LLM_THOUGHT
{stop_reason, text, tool_calls:["lsof_port"]}
seq=3
TOOL_REQUEST
{tool, argv, args, risk:"low", requires_root:false}
seq=4
SAFETY_CHECK
{decision:"allow", risk:"low", hits:[], rationale:[...]}
seq=5
EXECUTION
{argv, requires_root:false}
seq=6
EXECUTION_RESULT
{rc:0, stdout, stderr, duration, skipped_reason:"windows_mock"}
seq=7
AGENT_REPLY

8 CLI · audit list / show

CLI
kyagent audit list -n 20
列最近 20 条 trace · trace_id / user / 时间 / channel（mcp 或 LLM 后端名）
CLI
kyagent audit show <trace-id>
按 seq 顺序打印每个事件，按 kind 着色 · 单条 payload 截 1500 字

这就是赛题「异常回溯」的物理实现：出问题时，跑 kyagent audit show trace-xyz，就能看到完整推理链。

10 关键不变量

1
每条 trace 的 seq 从 1 开始严格递增：1, 2, 3, ...
2
同一 trace 内事件落盘顺序 = seq 顺序：受 trace._lock 保护
3
不同 trace 之间 JSONL 行可以交错，但每行原子（_jsonl_lock 保护）
4
SQLite 是权威源，JSONL 是流式镜像：JSONL 故障不影响 SQLite
5
JSONL 关闭后再来的 event 静默丢弃：不抛 NoneType（H1 修复）
6
audit.close(trace) 是幂等的：不会重复创建数据库行（INSERT OR REPLACE）
