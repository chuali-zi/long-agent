执行代理 + 沙箱
最小权限落地

对应文件 kyagent/executor/{sandbox,proxy}.py + configs/sudoers.kyagent。 这是赛题第 ④ 条「最小权限代理执行」的落地。 每一条设计都直接对应一种攻击。

1 设计原则 ↔ 攻击映射

设计防的是什么
永远只接 argv: list[str]，绝不调 shellshell 注入
默认以非 root 受限账户运行提权风险
requires_root 走 sudo -n -u root，依赖 sudoers 白名单不可控提权
forbid_root=True 时拒绝所有 root 提权防误启用
PATH 白名单 + 显式 which()命令路径污染
干净 env（过滤 LD_PRELOAD 等）共享库注入
preexec_fn：setpgid + RLIMIT_*失控进程 / 资源耗尽
communicate 带 timeout，超时杀整组超时挂死
stdout/stderr 截断到 output_cap输出炸内存
Windows 上 mock，永远不执行 Linux 工具开发态误操作本机

3 preexec_fn 工厂

preexec_fn 在 fork() 之后、exec() 之前在子进程里运行。这是设置 rlimit / 改进程组的关键时机。

★ executor/sandbox.py:33
def _preexec():
    # 独立进程组，便于整组超时 kill
    try: os.setpgrp()
    except OSError: pass

    # CPU 时间 / 地址空间 / 单文件大小 / 句柄数
    try: resource.setrlimit(resource.RLIMIT_CPU,
                            (cfg.rlimit_cpu_seconds, cfg.rlimit_cpu_seconds))
    except (OSError, ValueError): pass
    try: resource.setrlimit(resource.RLIMIT_AS, (mem_bytes, mem_bytes))
    except (OSError, ValueError): pass
    try: resource.setrlimit(resource.RLIMIT_FSIZE, (f_bytes, f_bytes))
    except (OSError, ValueError): pass
    try: resource.setrlimit(resource.RLIMIT_NOFILE,
                            (cfg.rlimit_nofile, cfg.rlimit_nofile))
    except (OSError, ValueError): pass
1
每个 setrlimit 都 try/except：某个 rlimit 在容器里可能不允许，单条失败不应阻止其它生效
2
setpgrp()：让子进程成为新进程组组长。超时 kill 时 killpg(pgid, SIGTERM) 一次性杀整棵子树
3
Windows 返回 None：subprocess.Popen 在 win32 上不接受 preexec_fn
C1
安全代价：这个 preexec_fn 在多线程父进程下与 fork() 组合是不安全的（glibc malloc 死锁、async-signal-safety）。 这就是为什么 supports_parallel_tool_execution 在 POSIX 上 gated off——详见 12-concurrency 的 C1。

4 build_clean_env · 双重 PATH 防御

executor/sandbox.py:75
base = {
    "LANG": os.environ.get("LANG", "C.UTF-8"),
    "LC_ALL": os.environ.get("LC_ALL", "C.UTF-8"),
    "HOME": os.environ.get("HOME", "/tmp"),
    "USER": cfg.account,
    "LOGNAME": cfg.account,
    "SHELL": "/bin/sh",
    "TERM": os.environ.get("TERM", "dumb"),
}
if cfg.restrict_path:
    base["PATH"] = os.pathsep.join(cfg.path_whitelist)

# extra 黑名单过滤
forbidden = {"LD_PRELOAD", "LD_LIBRARY_PATH", "LD_AUDIT",
             "PYTHONPATH", "BASH_ENV"}
for k, v in (extra or {}).items():
    if k in forbidden: continue
    base[k] = v
1
只放白名单变量：父进程的 env 没继承，KYAGENT_API_KEY 之类密钥不会泄漏给子命令
2
PATH 强制白名单：哪怕 restrict_path=False，默认值也是白名单
3
forbidden 黑名单：调用方传 extra={"LD_PRELOAD":"..."} 也会被静默过滤
4
TERM=dumb：避免 dmesg / journalctl 输出 ANSI 颜色码污染 stdout

5 ExecutionProxy 缓存三件套

commit e276c77 的优化点 — 把 executor 每次调用开销从「重新构造」降到「复用 + 偶尔 dict 拷贝」。

CACHE 1
_which_cache
命令 → 绝对路径，避免重复 shutil.which。即便缓存 None 也算命中（避免重复查找不存在的命令）。
CACHE 2
_env_template
干净 env 的不可变模板，每次执行只 dict(...) 浅拷贝
CACHE 3
_shared_preexec
preexec_fn 闭包，每个 Popen 复用同一份

7 _wrap_privilege · sudo 决策表

当前用户requires_rootforbid_root行为
kyagent（= target）False*直接跑，不 sudo
其他用户（≠ target）False*sudo -n -u kyagent -- <argv>
任意TrueTrue["/bin/false"] 占位失败
任意TrueFalsesudo -n -u root -- <argv>
FLAGS
sudo -n：非交互模式（绝不弹密码 prompt）；密码缺失 sudo 直接报错。
--：分隔 sudo 选项和实际 argv，防止 argv 里的 -X 被 sudo 当成自己的选项。

8 Popen 关键参数

proc = subprocess.Popen(
    final_argv,
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    stdin=subprocess.PIPE if stdin is not None else subprocess.DEVNULL,
    env=clean_env,
    cwd=cwd,
    preexec_fn=preexec,
    close_fds=True,
)
1
没有 shell=True：永远不调 shell，argv 直接 execve
2
stdin=DEVNULL：工具无法从 stdin 读到内容
3
close_fds=True：关闭所有非标准 fd，防止泄漏父进程文件描述符
4
preexec_fn：在 fork 后子进程里跑 setpgid + RLIMIT_*

9 _terminate_group · 杀整个进程组

1. os.killpg(os.getpgid(proc.pid), signal.SIGTERM)
   ↓ wait 300ms 优雅退出
2. if proc.poll() is None:
       os.killpg(os.getpgid(proc.pid), signal.SIGKILL)

→ killpg 而不是 kill：杀整个进程组
→ 子进程 fork 出来的孙子也跑不掉
→ 异常兜底：ProcessLookupError / PermissionError → proc.kill()

10 sudoers.kyagent · 系统侧最小权限

这是系统管理员的纵深防御：即便 kyagent 进程被劫持，攻击者也只能跑 sudoers 白名单里的命令；想拿 root shell 直接被 sudo 拒绝。

configs/sudoers.kyagent
Cmnd_Alias KY_READONLY = \
    /usr/bin/ps, /bin/ps, \
    /usr/bin/ss, /usr/sbin/ss, \
    ...

Cmnd_Alias KY_SVC_MUTATE = \
    /usr/bin/systemctl restart *, \
    /usr/bin/systemctl reload *, \
    /usr/bin/systemctl start *, \
    /usr/bin/systemctl stop *

kyagent  ALL=(root)  NOPASSWD: KY_READONLY, KY_SVC_QUERY, KY_PKG_QUERY, KY_FILE_META
kyagent  ALL=(root)  NOPASSWD: KY_SVC_MUTATE
kyagent  ALL=(ALL)   !/bin/sh, !/bin/bash, !/usr/bin/zsh, !/usr/bin/perl, \
                     !/usr/bin/python*, !/usr/bin/vi, !/usr/bin/vim, \
                     !/usr/bin/nano, !/usr/bin/awk, !/usr/bin/sed

Defaults:kyagent  !visiblepw, !env_keep, lecture=never, requiretty=false, \
                  log_input, log_output, iolog_dir=/var/log/sudo-io/%{user}
1
绝不出现 ALL：每条命令都列绝对路径
2
NOPASSWD 仅给只读 / 受控写：危险解释器（sh/python/awk）显式黑名单
3
!env_keep：sudo 跨权限边界时不保留任何环境变量（双保险）
4
log_input / log_output：sudo 自己也记审计（/var/log/sudo-io/），与 kyagent audit 互为对照
5
requiretty=false：因为 kyagent 作为 daemon 跑时没有 tty

安装步骤

sudo install -m 0440 configs/sudoers.kyagent /etc/sudoers.d/kyagent
sudo visudo -cf /etc/sudoers.d/kyagent
sudo useradd -r -s /usr/sbin/nologin kyagent
sudo usermod -aG systemd-journal kyagent

11 Windows mock 模式

def _run_windows_mock(self, argv, requires_root):
    return ExecutionResult(
        argv=argv,
        returncode=0,
        stdout=f"[mock][win32] would execute: {' '.join(argv)}\n"
               f"[mock][win32] requires_root={requires_root}\n"
               f"[mock][win32] real execution requires Kylin / Linux host.\n",
        ...
        skipped_reason="windows_mock",
        sudo_used=False,
        run_as="mock",
    )

Windows 上不真正跑命令，返回带 mock 标记的「假成功」。开发态 demo 可以走完整闭环：

（Windows）kyagent ask "查 80 端口"
  → MockBackend 路由到 lsof_port
  → ExecutionProxy._run_windows_mock 返回 mock stdout
  → MockBackend._summarize 把 mock stdout 当结果展示
  → 用户看到完整闭环（虽然结果是假的）

12 关键不变量

1
永远不调 shell：subprocess.Popen 永远不传 shell=True，argv 总是 list
2
PATH 总是白名单：哪怕调用方关 restrict_path，cfg 默认值仍然是白名单
3
forbid_root=True 时绝不 sudo root：会被 /bin/false 兜底
4
超时一定杀整组：killpg 杀进程组，防止 daemon 逃逸
5
stdout/stderr 一定截断：哪怕子进程吐 1GB，最终也只 64KB
6
任何异常都包成 ExecutionResult：上层永远不需要 try/except executor.run
