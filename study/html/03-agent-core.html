5 ThreadPool 生命周期

agent/core.py:77 · 懒创建
def _ensure_pool(self):
    if self._tool_pool is None:
        self._tool_pool = ThreadPoolExecutor(
            max_workers=4, thread_name_prefix="ky-tool"
        )
    return self._tool_pool

def shutdown(self):
    if self._tool_pool is not None:
        self._tool_pool.shutdown(wait=False)
        self._tool_pool = None
NOTE
max_workers=4 是保守上限——多了 GIL 抢锁，少了无法吃满 IO。 正常路径下 ask() 结束所有 worker 已 join，shutdown 是给「主动释放 Agent」用的。

7 _is_parallel_safe — 五重 AND

C2 修复后的版本，五重 AND 全过才允许并行。

1
工具必须已注册（registry.get 不为 None）
2
工具必须是 read_only = True（写操作不并行）
3
C2 第一道防线：guardrail.llm_reviewer 必须为 None（避免预检 vs 内检不一致）
4
参数能过 validate + build_argv
5
Guardrail 预检 verdict 是 ALLOW（CONFIRM/DENY 都走串行）

9 SYSTEM_PROMPT 行为规范

写给 LLM 的指导，但不是安全机制——LLM 偏离指令时仍然受 Guardrail / sandbox 兜底。

禁止假装已执行
所有动作必须 tool_use，不能在文本里假装执行命令
小步推进
每次只调 1-3 个工具，鼓励链式而不是 fanout
变更前先查状态
调 svc_restart 前先 svc_status
回复先结论后证据
给运维人看的，不要客套
明确禁止
拼 shell 字符串、幻觉命令输出、建议绕过安全的命令

10 关键不变量

1
每一次 ask() 都开一条 Trace 并 close（无论 LLM 报错还是超 max_iterations）
2
每一次 tool_use 都至少有 4 条审计事件：TOOL_REQUEST → SAFETY_CHECK → EXECUTION → EXECUTION_RESULT
3
self.confirm() 只在主线程调用（C2 第二道防线兜底）
4
tool_results[idx] 与 tool_uses[idx] 顺序对齐
5
DENY 路径不会创建子进程（短路返回，executor.run 没被调用）
6
CONFIRM 路径在 ask 单次模式下等价于 DENY
