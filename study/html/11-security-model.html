CHAPTER · 11 · SECURITY MODEL

安全模型总览
六层防御 · 多层独立失效不耦合

不引入新代码，而是把前面各模块的安全机制串成一张「全景图」。 任何一条危险命令都要穿透 L4 → L3 → L2 → L1 才能落地。 每一层独立失效都不会让攻击成功。

1 防御层（从外到内）

L1
系统层 · /etc/sudoers.d/kyagent
受限账户 kyagent（nologin shell）· NOPASSWD 白名单仅允许特定绝对路径命令 · 显式黑名单 sh / bash / python / awk / sed · log_input / log_output 系统侧 sudo 审计
L2
进程层 · ExecutionProxy.run
永远 list[str] argv（绝不 shell=True）· PATH 白名单 + which() 强制解析 · clean env 洗掉 LD_PRELOAD / LD_LIBRARY_PATH 等 · preexec_fn setpgid + RLIMIT_CPU/AS/FSIZE/NOFILE · communicate(timeout=30s) + killpg 进程组级超时 · stdout/stderr 截断 64KB · forbid_root 禁用 root 提权
L3
护栏层 · Guardrail
27 条规则覆盖 rm / dd / mkfs / chmod / chown / curl|sh / 反弹shell · 工具声明 risk 作为下限（CRITICAL 不可降）· 可选 LLM 复审（只能升级）· Policy: critical→deny / high→confirm / medium→confirm
L4
工具层 · Tool.validate + build_argv
JSON Schema required + type 校验 · _safe_path 禁路径符号 + 敏感文件黑名单 · _validate_unit 禁 shell 元字符 + 核心服务黑名单 · shell-meta 黑名单（; | & $ ` \n）· 不暴露 raw shell · 不暴露 install / remove / mask / disable
L5
LLM 协议层 · Agent.core
LLM 只能通过 tool_use 调命令 · 未知工具 / 参数错 → ERROR 兜底 · CONFIRM 必须主线程交互（C2 第二道防线）· 单次 ask 模式 confirm = always False · max_iterations 上限 8（防 LLM 循环）
L6
审计层 · Audit
全程 7+ 段事件落地（SQLite + JSONL）· SAFETY_CHECK 含完整 verdict / hits / rationale · EXECUTION_RESULT 含真实 argv / rc / duration / sudo · 任何拒绝路径都写 ERROR 事件留证据

3 信任边界图

4 不可绕过的强制路径

任何一次工具调用必经的代码路径，不可绕过、不可短路。

4.1 在 Agent 主循环里（_handle_tool_use）

必经 1
tool = registry.get(tu.name) — 工具必须已注册
必经 2
tool.validate(tu.input) — 必须类型/必填通过
必经 3
tool.build_argv(cleaned) — 必须工具自己的清洗通过
必经 4
audit.event(TOOL_REQUEST) — 必须写审计
必经 5
guardrail.check_argv(argv, declared_risk) — 必须过护栏
必经 6
audit.event(SAFETY_CHECK) — 必须写裁决
分支
if DENY: return [denied] — 短路，executor 不启动
分支
if CONFIRM: confirm() 拒绝 → return [denied]
必经 7
audit.event(EXECUTION) — 写"即将执行"
必经 8
executor.run(argv, requires_root) — 必须经过 executor
必经 9
audit.event(EXECUTION_RESULT) — 必须写结果
SYM
MCP server _call_tool 路径形状完全一致——这是把「安全 + 审计」作为强制中间件的物理实现。

5 失败模式分析

FAILURE · 5.1
LLM 后端故障
网络抖动 / 限流 → 不让进程崩，写 ERROR + 友好提示返回
FAILURE · 5.2
非 utf-8 输出
_truncate 用 errors="replace" + repr 兜底，永远不抛 UnicodeError
FAILURE · 5.3
sudo 不可用
sudo -n 在密码缺失时直接 rc=1 + stderr 提示，附在 ToolResult
FAILURE · 5.4
SQLite 写入失败
极端情况（磁盘满）抛 OperationalError · 已知薄弱点
FAILURE · 5.5
JSONL 写入失败
不影响 SQLite · trace 仍可回放，只是 JSONL 通道丢一行

8 一句话总结

CORE
多层独立失效不耦合。

LLM 失守 → 工具层兜
工具层失守 → Guardrail 兜
Guardrail 失守 → sandbox 兜
sandbox 失守 → sudoers 兜
任何一步行为都被审计源记录

任意单一层被绕过都不会让攻击成功。这是赛题「杜绝误删库、误操作、危险注入」的物理实现。
